# Retrieval v3 — оценка на датасете rag_eval_dataset_100 (внешняя разметка ChatGPT)

Источник: датасет 100 размеченных вопросов по документам `data/raw`
(92 отвечаемых с точными evidence-needle и координатами страницы/абзаца,
8 неотвечаемых; сплит 80 test / 20 dev). Разметка и метрики — сторонние
(`data/rag100/evaluate_retrieval.py`, использован без изменений).
Адаптер: `scripts/evaluate_rag100.py`.

## Метод привязки

Чанки нашего индекса сопоставлены с юнитами датасета: PDF — по номеру страницы,
DOCX — по текстовому вхождению абзаца (нумерация абзацев у разметчиков отличается
от нашей, поэтому только текстовая привязка; 632 DOCX-чанка привязаны, 26 сирот).
Покрытие: все 55 уникальных gold-юнитов доступны нашим чанкам (55/55).
Для каждой конфигурации два набора предсказаний: reranked top-10 (candidates)
и итоговый контекст top-6 (selected — то, что получает LLM).
Abstention retrieval-уровнем не реализован (поле `abstained=false`); метрика
отказов здесь не применялась (она оценена end-to-end в 05).

## Интерпретация

1. **BGE-M3 E2 — лучший вариант именно на этом датасете**: он строго доминирует
   по ранговым метрикам и единственный улучшает обе метрики уровня документа
   и источника. Небольшой объём (n=74) не даёт значимости на уровне 95%,
   но знак согласован по всем метрикам и совпадает с ростом needle recall (86 vs 84).
   Причина: русскоязычные вопросы с перефразом — сильная сторона BGE-M3;
   кроме того, его selected-контекст не переупорядочивается coverage-селектором,
   поэтому ранговые метрики сохраняются.
2. **Coverage (V2/V3F) здесь не помогает**: вопросы преимущественно
   одно-требовательные (один gold-документ, один needle), эффект мультитребовательного
   покрытия не проявляется, а переупорядочивание селектором снижает ранговые метрики
   selected-контекста (Unit H@1 0.473 против 0.716 у baseline; ΔMRR −0.117 ± 0.059).
   Дополнительные проходы декомпозиции дали +0.013 на unit H@5 уровне candidates.
3. **MMR ≈ baseline**: нейтральный результат, как и на внутренних сплитах.
4. Ошибки, общие для всех конфигураций: 3 вопроса не покрываются никем
   (both-miss), включая Q096 (табличный фрагмент без привязки к юнитам) —
   см. разбор ниже.

## Ограничения оценки

- n=74 (test) / 18 (dev) — статистическая мощность низкая; выводы по знаку
  и согласованности, не по значимости.
- Табличные чанки DOCX не привязаны к юнитам датасета (`table_row`); если gold
  попадает в таблицу, вопрос может занижаться у всех конфигураций одинаково.
- 26 DOCX-чанков стали сиротами привязки (текст не найден среди юнитов) —
  обычно это таблицы/повторы; на предсказания влияет мало, но возможны потери.
- Метрики датасета проверяют поиск документа/юнита, а не качество ответа LLM;
   end-to-end на этом наборе не оценивался.

## Ошибки, общие для всех конфигураций (test)

| ID | Причина |
|---|---|
| Q096 | Табличный фрагмент; наш чанк не привязан к юнитам датасета — предсказание пустое у всех |
| 2 вопроса | Gold-юнит есть в индексе, но не входит в top-6 selected ни у одной конфигурации (doc hit@6 = 91/92, unit-покрытие ниже) |

## Вывод для выбора варианта

- **Максимум качества на внутренних документах при допустимой задержке ~1,3–1,5 с/вопрос: BGE-M3 E2.**
- **Быстрый и стабильный вариант (0,15–0,25 с/вопрос) с качеством на 2–6% ниже: V3-Final (E5).**
- Coverage-селектор оправдан только на многотребовательных вопросах
  (подтверждено CUAD, этап 02); для этого датасета он нейтрален/вреден по рангам.
- Направление улучшения: BGE-M3 (dense+sparse) в связке с coverage-selection —
  потенциально объединяет лучшее из обоих, требует отдельной валидации.
