# Итерация G — LLM Enrichment (карточки фактов + синтетические вопросы, doc2query)

Задача: LLM один раз при индексации строит семантическую память по регламентам
(карточки фактов, типовые вопросы), которая подключается как дополнительный
поисковый канал. Оценка — только retrieval (по указанию: проверка ответов LLM
отложена). Gold-разметка complex50 в создании карточек не используется.

## Построение (`scripts/build_enrichment.py`)

- Вход: 439 clauses (clause store), батчи по 4 пункта, Qwen2.5-3B (llama.cpp,
  `--parallel 4`), constrained JSON (схема совместима с llama-грамматикой:
  без union-типов), промпт на русском.
- Детерминированная валидация: quote обязана быть подстрокой пункта;
  цифры сроков — из цитаты; у вопроса есть пересечение лексики с пунктом.
- **Результат: 322 карточки фактов + 949 синтетических вопросов, 0 сбоев
  батчей, 17 минут** (manifest: `data/enrichment/enrichment_manifest.json`).

## Поисковый канал (`navigator/enrichment_search.py`)

- Векторный индекс карточек (BGE-M3), кэш эмбеддингов с fingerprint модели.
- На запрос: top-8 clause_ids через ближайшие вопросы (E1) / +факты (E2) →
  полные пункты подмешиваются в кандидаты multi-hop с origin "enrichment"
  (score −1.0, ниже реранкерных). Конфиги `retrieval_e{1,2}_*.yaml`.

## Результаты (complex50, retrieval-only, n=50)

| Конфиг | Clause Recall | Fact Coverage | All Found |
|---|---:|---:|---:|
| E0 = H4 (multi-hop) | 0.9270 | 0.9283 | 78% |
| E1 = E0 + вопросы | 0.9270 | 0.9283 | 78% |
| E2 = E1 + факты | 0.9270 | 0.9283 | 78% |

E0=E1=E2 побайтово: канал обогащения **не изменил покрытие ни на одном
вопросе**.

## Интерпретация (нейтральный результат)

1. Retrieval уже насыщен: 92.7% при oracle 100%; остаток — 2 непарсируемых
   места (NM_para63) и редкие hard-кейсы. Доказательства, которые канал
   обогащения мог бы добавить, уже находятся multi-hop.
2. Механизм корректен и полезен как инфраструктура: на корпусах с большим
   терминологическим зазором (пользователь не знает слов регламента) или при
   более слабом базовом retrieval эффект doc2query должен проявиться. Здесь
   бенчмаркные вопросы сформулированы близко к тексту регламентов.
3. Стоимость канала невысока (один раз 17 мин offline + мгновенный поиск),
   поэтому конфиги E1/E2 сохранены, но по умолчанию выключены
   (`enrichment_search: false`).
4. Для различения «канал не работает» vs «уже всё найдено» можно проверить
   E1/E2 на подвыборке вопросов, где E0 теряет доказательства (all_found=0):
   различий тоже нет — значит теряемые пункты не достижимы ни через вопросы,
   ни через факты (проверено per-question).

## Инфраструктурные находки (зафиксированы)

- llama.cpp отклоняет JSON-схемы с union-типами (`["string","null"]`) → HTTP 400.
- `--parallel N` делит контекст на слоты (`-c/N`): при `-c 8192 -p 4` слот
  2048 токенов, длинные промпты получают 400. Для verified-генерации:
  `-c 16384 -p 4` + капы блоков (2200 суммарно / 900 на блок) + max_tokens 800.
- Кэш Retriever'ов в одном daemon-процессе на 8 ГБ VRAM даёт накопление
  моделей по числу конфигов → деградация до минут на вопрос. Один процесс =
  один прогон; daemon целесообразен только с общим бэкендом моделей.
