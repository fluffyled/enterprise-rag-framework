# Итерация E — проверяемая генерация (H5): evidence blocks → план → верификация

Гипотеза: если LLM ссылается на структурированные блоки по ID, а каждый шаг
проходит детерминированную проверку подтверждения, ответы станут полнее
(план фиксирует требования) и без выдумок (верификация отбрасывает неподтверждённое).

## Реализация (`navigator/verified_answer.py`)

1. Evidence blocks: документ + пункт + полный текст + ID (капы: 2400 симв/блок,
   5800 суммарно — в СИМВОЛАХ, т.к. словесный счёт токенов занижает BPE в ~2.4 раза).
2. LLM-план (русский промпт, constrained JSON): steps[{action, actor, condition,
   deadline, evidence_id}] + missing_information. 1–6 шагов.
3. Детерминированная верификация: evidence_id существует; цифры шага ⊆ цифрам
   блока; стеммированное (первые 5 символов) пересечение токенов ≥ 0.4 (действие)
   и ≥ 0.5 (поля). Неподтверждённые поля обнуляются (шаг сохраняется),
   неподтверждённое действие уходит в missing.
4. Ответ: поддержанные шаги с дословными цитатами блоков; нет поддержанных —
   отказ с явным списком недостающего.

Три найденных и исправленных бага пути: union-типы в JSON-схеме (llama 400),
англоязычный промпт (верификация русских блоков давала 0 совпадений),
недооценка длины промпта словесным счётчиком (400 на больших контекстах).

## Результат (complex50, контекст H1, финальный прогон, 0 ошибок из 50)

| Конфиг | Step Recall | Complete@all | False Abst | Unsupported |
|---|---:|---:|---:|---:|
| Q0 + обычная генерация | 0.461 | 8% | 6% | 0.337 |
| H1 + обычная генерация | 0.426 | 10% | 4% | 0.365 |
| **H1 + H5 verified** | **0.558** | **22%** | 14% | 0.160 |
| Oracle + обычная генерация | 0.636 | 14% | 2% | 0.000 |

- **H5 — единственная конфигурация, конвертировавшая прирост retrieval в
  качество ответа**: Step Recall выше baseline на +0.10, Complete@all 22%
  (лучший результат исследования; oracle с обычной генерацией — 14%).
- Unsupported quote rate с 0.34–0.38 (обычная генерация) до 0.16 — верификация
  работает; остаток 0.16 — цитаты блоков с обрезкой (кап 2400 символов).
- Цена: 14% ложных отказов (строгая верификация иногда отбрасывает верные,
  но не дословно совпадающие формулировки) и медленная генерация
  (медиана ~56 с на вопрос при -c 16384; ускорение — отдельная задача).
- **Качественная оговорка**: шаги H5 — описательные фрагменты («обращение
  считается неактуальным»), а не отшлифованные инструкции; все они, впрочем,
  подтверждены точными пунктами. Финальная формулировка — задача более
  сильной LLM (G-эксперименты, отложены по решению).

## Вывод итерации E

Проверяемая генерация **принята** как режим для сложных вопросов: она решает
главную проблему исследования (потеря фактов при передаче в LLM) за счёт
структурированного плана и детерминированной сверки. Рекомендация: H1/H3
retrieval + H5 generation для quality-сценария; latency улучшать переносом
плана на слоты/квантование.
