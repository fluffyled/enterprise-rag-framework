# Generation Research v2

Ветка `experiment/generation-v2` основана на `sevsese` @ `abe0c6cd9a099771d4ac43e106bbfbaf23e1ad82`. Единственная модель в новых запусках — локальная Qwen3.5-4B Q4_K_M, llama.cpp CUDA, окно 4096 токенов. Фактическое оборудование — RTX 3050 Laptop 4 ГиБ, занято около 3541 МиБ VRAM во время пилота по снимку nvidia-smi. Пиковый расход и время загрузки отдельно не измерялись.

## Аудит базы

- Исходный `navigator.answer.answer` передаёт нумерованные предложения, просит выбрать до трёх ответов и пяти шагов, ограничивает вывод 300 токенами. Многострочные пункты обрабатываются как предложения. В результирующем ответе остаются цитаты из индекса.
- `navigator.verified_answer.verified_answer` строит план H5 из блоков. Обрезает один блок до 2400 символов, пропускает блоки после исчерпания общего бюджета 5800 символов. Запрашивает 1–6 шагов, схема пропускает до восьми, лимит вывода 800 токенов. Проверяет наличие ID, пересечение стеммов и цифры, но такое пересечение не подтверждает правильность роли, порядка или отрицания.
- В `evaluate_complex_rag.py` обычный режим вызывает свой `call_llm`, H5 вызывает `verified_answer`. Часть метрик evaluator начисляется за содержание цитаты. Показатели из отчёта retrieval не переносились в новое сравнение.
- Старые C0/C1/C2 воспроизводимы по `answering/core.py`, `answering/v2/pipeline.py`, `scripts/evaluate_generation_v2.py` и `reports/generation-v2/oracle-complex50-qwen35-v25.jsonl` в основном worktree. C0 выбирает предложения с другой схемой, C1 извлекает факты по группам, C2 добавляет проверку и исправление. Это другие реализации. Каждая из 10 ошибок C1 и C2 сопровождалась `finish_reason=length`, 1250 токенов вывода. Общий контекст на этих вызовах не достигал 4096. Ранее заявленные 55,4% смыслового покрытия используются как справочный ориентир из ТЗ. Локальный отчёт полного прогона содержит отдельный лексический proxy.

## Эксперимент

G0 и G0-H5 вызывают исходные функции без изменений. G1 формирует структурированный ответ напрямую за один вызов. G2 извлекает факты по группам и собирает шаги с точными цитатами. G3 выделяет запрошенные аспекты отдельным вызовом и связывает их с фактами. G4 проверяет утверждения по источникам, ищет пропуски и допускает одну адресную попытку исправления. Все новые варианты используют seed 42, температуру 0, отключённый thinking и схему JSON. При техническом сбое разрешён один повтор. При обрезке бюджет увеличивается максимум до 2000 токенов с учётом входа.

На HQ002 и HQ004 каждому варианту передавались одинаковые Oracle-цитаты и исходный вопрос. Смысловую оценку ниже выполнил один аннотатор (ассистент) по видимому тексту резюме и шагов. Эталонные факты использовались только при оценке. Факт оценивался 1 при полном совпадении смысла, 0,5 при потере существенной детали и 0 при отсутствии. Цитата сама по себе балл не добавляет. В таблице для HQ004 факт о закрытии через 14 дней получил 0,5, так как в действии G2 отсутствует условие о завершении работ. Статус `answered` сам по себе не обозначает полноту.

Это подтверждает восстановление конкретного dev-случая. Обобщение на остальные девять старых сбоев пока не проверено. На HQ004 планирование аспектов потеряло деталь, которую сохранил G2. Верификация её не восстановила. Размер пилота не позволяет делать обобщение или оценивать доверительные интервалы.

## Воспроизведение

Из рабочей копии, когда Qwen3.5-4B доступна на локальном порту 8091:

```powershell
. D:\хакатон\project-env.ps1
..\.venv313\Scripts\python.exe -m scripts.run_generation_research --dataset ../hierarchical_rag_plan_and_dataset_50.zip --output reports/generation-research/repeat.jsonl --limit 2
..\.venv313\Scripts\python.exe -m scripts.run_generation_research --dataset ../hierarchical_rag_plan_and_dataset_50.zip --output reports/generation-research/retry-repeat.jsonl --case HQ014 --modes G2-no-retry G2
```

Трассы пилота лежат в `reports/generation-research`. Для H1, H4 или быстрого профиля преобразуйте сохранённый `per_query_results.json` командой `python -m scripts.freeze_generation_contexts <trace> <fixed.jsonl>`. Затем передайте `--fixed <fixed.jsonl>` в команду запуска. Адаптер также принимает `generate_answer(question, documents, endpoint, mode)` с документами Haystack. Каждый результат имеет отпечаток входа. Baseline G0 не сохраняет сырой ответ через свой текущий контракт. В ранней пилотной трассе G1–G4 сохранены сырые ответы и расходы, новый runner дополнительно сохраняет текст системного промпта и лимит каждой попытки.

## Оставшиеся измерения

В снимке `sevsese` есть отчёт и профили H1/H4. На этой машине не обнаружены точные выдачи `per_query_results.json`, grouped split первого агента, его Clause Store, BGE-M3 и BGE reranker. Пилот использует исходный dev-раздел архива. До получения этих артефактов доступны Oracle и импорт предоставленных выдач. Полная матрица G0–G4 на H1 и Oracle, групповой test, независимая повторная разметка, анализ ложноположительных проверок и парные интервалы остаются незавершёнными. G2 — кандидат для следующей проверки, данных для выбора production-конфигурации пока нет.
