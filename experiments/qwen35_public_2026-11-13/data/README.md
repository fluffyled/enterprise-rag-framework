## Датасет для алайнмента (граундинга) способности LLM отвечать на вопросы по документам (RAG)

Этот датасет был собран на основе **13к** разных статей из русской Википедии с помошью синтетических вопросов и ответов **gpt-4-turbo-1106**.

Датасет содержит **4047** уникальных кластеров, т.е. комбинаций из документов - улосвная симуляция "найденных результатов" в Retrieval системе. Подробнее описано в разделе "Общие этапы сборки этого датасета".

Общий объем датасета - **50210** уникальных диалогов.

В колонке conversation представлен диалог в huggingface формате с ролями: documents, user, assistant. Общая длина диалогов подразумевает модели в основном с 10k+ контекста.

**Важно**: По логике граундинга RAG - роль assistant специально повторяется дважды в конце. Первый ответ ассистента - JSON словарь с массивом id (int) документов. Второй - уже полноценный ответ на вопрос пользователя по документу. \
Предполагается, что модели не будут обучаться на самих текстах документов и вопросах пользователей - только на ответах для ассистента. 

**Это обновленная версия датасета.** В отличие от старых датасетов Vikhrmodels/Grounded-RAG-Chat-RU и Vikhrmodels/Grounded-RAG-QA-RU этот содержит большее количество типов разных "good" вопросов, значительно улучшенные этапы пост и препроцессинга, более честную разбику нв train и test части.

### Цель датасета
Научить модели отвечать на сложные и простые вопросы по нескольким документам (от 1 до 5) разного формата в формате чата (отдельная роль для документов).

Кроме того, модель учится отклонять любые вопросы, ответы на которые не содержатся в найденых документах - для этого предполагается использование другой модели (болталки).

Как бонус, перед каждым ответом модель будет генерировать отдельную реплику содержащуюю выбор документов в которых находися релевантная информация для ответа, что позволяет лучше контролировать и следить за моделью (граундинг).

### Формат представления документов
Роль documents представляет из себя список словарей с описанием контента документов, с примнением json.dumps(array). \
Контент документов представлен в **3** случайных форматах: **Markdown**, **HTML**, **Plain Text**. Контент кажддого документа - случайный чанк из статьи длиной до 4к символов.

```json
[
  {
    "doc_id": (0..5),
    "title": "(null or str)",
    "content": "(html or markdown or plain text)"
  }
]
```

### Общие этапы сборки этого датасета
1. Парсинг русскоязычных статей википедии (около 30к), в 3 разных форматах текста. Выбор случайного чанка до 4к символов в каждом документе.
2. Фильтрация и кластеризация с помошью AgglomerativeClustering и e5-large-multilingual (около 4к уникальных кластеров с 13к документами). Каждый кластер - от 2 до 5 документов.
3. Генерация синтетических вопросов по кластеру документов (gpt-4-turbo-1106), с учетом комплексных вопросов по нескольким документам одновременно. \
Для каждого кластера 14 вопросов: 10 на которые есть ответы в документах (good) и 4 на которые точно ответа в кластере нет (ood). \
При генерации каждого вопроса использовался CoT для выбора id документов из кластера по которым задавать вопрос. \
OOD вопросы включают в себя случайные интрукции не связаные с предоставленными данными -> модель учится их игнорировать.
5. Случайный дропаут кластеров и полей title (установка на null) из небольшого количества документов, кластеры удалялись только для ood воропосв
6. Генерация синтетических ответов с gpt-4-turbo-1106 для пары (кластер, вопрос), с указанием в каких докуметах искать ответ (из этапа 3).
7. Фильтрация ответов (удаление очевидно ошибочных), постпроцессинг и аугментация исходных вопросов пользователей.
8. Сборка в диалоги и разбиение на train и test части со стратификацией по полю type (тип вопроса). В train части нет кластеров из test части.
