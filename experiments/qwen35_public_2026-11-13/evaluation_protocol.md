# Методика и ограничения оценки

Все нейросетевые вызовы выполняет один локальный сервер Qwen3.5-4B Q4_K_M через CUDA. Подготовка JSON, работа с файлами и расчёт статистики выполняются обычным Python; это не CPU-инференс модели. Код, данные, кэши, временные файлы и результаты находятся на D:. Существующая модель повторно не скачивалась. Исходные индексы и ветки проекта не менялись.

## Данные и разбиение

Grounded-RAG-RU-v2: официальный train 50 010 / test 200. Для настройки скачан первый train-shard на 25 005 строк; обучение не проводилось. Выбран dev 24 (12 good, 12 OOD), test 32 (16 good, 16 OOD), seed 20261113. Отбирались примеры с вопросом и документами до 2600 токенов фактического токенизатора. Это ограниченный срез для контекста 4096, а не полный benchmark. Длинные примеры исключены целиком, не обрезаны по наличию ответа. Размеры и хэши файлов находятся в dataset_manifest.json.

В conversation две различные финальные реплики assistant: JSON с relevant_doc_ids и эталонный текст. Они используются только для оценки; генератору передаются вопрос и документы. Исходный system из датасета заменён фиксированным экспериментальным prompt. Форматы HTML/Markdown/plain унифицированы одинаково для всех конфигураций; номера пунктов не выдумывались. Исходные чанки могут начинаться или заканчиваться посередине HTML/положения. Это ограничение исходных данных, а не доказательство полноты контекста.

MultiDoc2Dial: 4 примера из train для dev и 8 из validation для отдельной проверки. Официальный test не использован. Переданы gold-окружающие text_sec — oracle-контекст, а не найденные Retrieval фрагменты. Сохранены история диалога, references, исходные span offsets и эталон. Не все respond_solution являются процедурами; не каждый grounding span является обязательным действием. Два заранее отмеченных шумных примера остаются в полном срезе, дополнительно показан clean sensitivity из 6. Нельзя переносить эти результаты на английский benchmark в целом.

Группы — связные компоненты общего cluster, точного SHA256 нормализованного текста или непустого заголовка. Между dev/test пересечений компонентов нет. В test RU 15 групп, MD 8. Смысловые дубликаты без совпадающих заголовков/текстов полностью не исключены. У test 9 многодокументных gold-примеров, 13 отвечаемых примеров с отвлекающими документами. Процедурные/условные вопросы проверяются дополнительно на MD; официальной разметки обязательных условий в RU нет.

## Фиксация эксперимента

A0 — сохранённый выбор исходных предложений из navigator/answer.py коммита напарника; возвращается цитатный ответ, без свободного пересказа. Снимок исходника, prompt, chat template и параметры сервера в frozen/. A1 меняет только единицы выбора: целые абзацы/доступные структурные блоки вместо предложений. Prompt, schema и decoding A0/A1 одинаковы. Автоматическая структура A1 ограничена абзацами и видимыми маркерами списков; это не полноценный юридический парсер.

A2 v2 — выбор evidence-блоков, затем краткий русский ответ только по выбранным блокам. Ранний A3 v2 совместно выдавал claims/actions. Строгий A3 procedure v3 отдельно извлекает actions с actor/condition/deadline/evidence_ids и null для неподтверждённых полей, затем отдельным вызовом формирует ответ. Исправление протокола после первоначального test раскрыто в procedure_protocol_repair.json; исходный v2 не переписан. A4 v2 допускает partial на стадии выбора и ответа. Неполнота обозначается статусом; для UI потребуется явное отображение этого статуса. Не проверялось, понимает ли пользователь интерфейса такую неполноту.

Первоначальные A2/A3/A4 v0 сохранены в runs/dev/A2, A3, A4. После ложных отказов на dev в v2 заменён слишком широкий запрет сроков/действий на требование их явного подтверждения. Отдельная диагностическая подсказка с примером не вошла в финальный prompt. v0 не запускался на test. Промпты и выборки v2 зафиксированы в pretest_lock.json до первого test-вызова; после просмотра test ничего не перенастраивалось. Консервативный dev-кандидат — A2 v2; итоговый test может опровергнуть его пригодность.

A2 против A0 одновременно меняет блоки, число вызовов и способ формирования ответа. Поэтому улучшение нельзя приписывать исключительно Evidence-first. Небольшой дополнительный one-step контроль и перестановки контекста выполняются только на dev и не являются основанием доказанного выигрыша.

## Что считается измерением

Точные метрики: схема JSON через jsonschema по фактическим HTTP-ответам; отдельная валидация программного контракта; good/OOD решения; TP/FP/FN отказов; совпадение gold ID документов; wall-clock latency; token usage. Существование ID — только синтаксическая/структурная проверка. Gold document ID Precision/Recall не названы семантической точностью цитат.

False Refusal = good со статусом insufficient / все good. False Answer OOD = OOD со статусом answered или partial / все OOD. Error и conflict не маскируются под корректный отказ и показываются отдельно. Abstention Precision = правильные OOD-отказы / все insufficient; Recall = правильные OOD-отказы / все OOD; F1 — гармоническое среднее. Answer Correctness оценивается отдельно на good; правильность отказов не увеличивает эту метрику.

**Семантические численные показатели — оценки того же Qwen3.5-4B, не независимая истинная разметка.** Отдельных генеративных моделей или облачного judge не использовалось. Промпт судьи, вход, ответ, схема и usage сохранены. Судья видит reference после завершения генерации; reference не поступает генератору. Согласованные ошибки генератора и судьи возможны. Эти числа нельзя выдавать за доказанные истинные Faithfulness/Correctness.

Судья оценивает самостоятельные факты внутри каждого выданного текстового элемента. Faithfulness = supported_facts / total_facts; UCR = 1 − Faithfulness, микроусреднение по оценённым фактам. Дословная цитата может потерять отрицание или условие, поэтому дословность сама по себе не превращается в 100% подтверждённость. Нет утверждений — показатель не определён, а не 100%. Повторённые выданные элементы учитываются повторно; сегментация и число фактов также зависят от судьи.

Answer Correctness: 0 — отсутствующий/неправильный ответ, 0.5 — правильная существенная часть, 1 — правильный полный ответ без неподтверждённых добавлений. Это дискретная оценка смысла с reference и документами, не EM/лексическое F1. Essential reference coverage — вспомогательная оценка покрытия существенных единиц эталона.

Citation Precision = полностью поддерживающие связанные элементы ссылки на документы / все выданные ссылки. Citation Recall = подтверждённые факты с достаточной оценённой поддержкой указанными документами / все факты. Частичная поддержка сложного элемента не считается полной поддержкой всей ссылки. Из-за такого консервативного определения длинные A1-блоки могут получать меньшую precision. Это не официальная реализация ALCE и не результат независимого NLI-классификатора.

CPR оценивается только по 6 явно проверенным условиям в 4 MD-примерах. Procedure Completeness — по 7 проверенным единицам ответа в 4 MD-примерах. Полный список и буквальные подтверждающие цитаты — procedure_annotations.json, всего 5 различных аннотированных случаев. Разметку подготовил агент по исходному тексту и вопросу до test-предсказаний; независимой человеческой проверки нет. Это исследовательские единицы содержания, не официально размеченная юридически обязательная последовательность. Порядок не размечен. Для RU CPR и полнота процедуры — N/A. Нельзя автоматически считать весь gold span обязательным условием/шагом.

Полный UAR нельзя считать только по полю actions: действия встречаются и в claims. В self-judge CSV сохранён лишь технический structured-action unsupported diagnostic, не полный UAR. Исследовательский UAR отдельно размечен агентом по всем действиям итогового текста только для двух MD-кейсов. Глобального независимо проверенного UAR нет. При отсутствии actions — N/A, не ноль. «Полезный partial» требует прямого подтверждённого ответа на часть вопроса; тематическое сходство не считается полезностью. Критические флаги судьи требуют отдельной проверки; отсутствие флага не доказывает отсутствие опасной ошибки.

## Статистика и ресурсы

Сравнения парные по одинаковым case_id. 2000 cluster bootstrap повторов, seed 20261113; компонент документов выбирается с возвращением целиком. Интервалы описывают только этот небольшой срез. Для семантических сравнений дополнительно требуется совпадающее покрытие оценкой; пропущенные/неоценённые случаи показываются явно. Нельзя делать вывод о значимости, если CI включает ноль; даже CI без нуля не устраняет систематическую ошибку self-judge. Датасеты не объединяются в общий результат.

Основной test запущен последовательно на одном server slot, без конкурирующих экспериментальных запросов. Некоторые dev-v0/v2 вызовы пересекались в очереди; dev latency не используется как контролируемое сравнение скорости. Между arm порядок фиксированный, без повторов, возможен температурный дрейф GPU. p95 на 8 MD-примерах нестабилен.

VRAM снимается nvidia-smi примерно раз в 0.5 секунды плюс время команды: это память всего устройства, включая интерфейс, не точный пик процесса и не доказательство максимального allocation. Working set — наблюдаемый Windows RSS процесса сервера, может включать mapped файлы; отдельные short-вызовы могут не иметь отсчёта. Выводы об эксклюзивной памяти модели по этим цифрам не делаются.

Веса 40/25/20/15 — только предложенная пользователем исследовательская гипотеза. Итоговый weighted score не применяется: высокий средний балл способен скрыть одну выдуманную обязательную дату/согласование. Решение требует отдельных ограничений на критические ошибки, OOD-ответы, ложные отказы, полноту и скорость. Замена основной конфигурации не производится автоматически по одному среднему показателю.


## Результат проверки оценщика

Выборочная сверка показала, что Qwen-судья смешивает пропуск требования с неподтверждённым фактом и ставит ложный critical flag. Поэтому все его численные семантические оценки остаются диагностическими и не используются как доказательство улучшения. Для сравнения диагностик применяется общий пересекающийся набор успешно оценённых case_id всех arm; исходные оценки и пропуски сохранены. Отдельный source review агентом на малом явно указанном наборе не является независимой человеческой разметкой.
