# Проверка первой версии второй части

Дата: 12.11.2026. Новый модуль answering/, отдельный UI answer_app.py, Qwen3.5-4B Q4_K_M, llama.cpp b12284. Реальный корпус — 20 файлов, побайтно совпадающих с присланным ZIP. Исходные вопросы, цитаты и документы не публикуются; локальные логи находятся в reports/.

## Что проверено

- 34 pytest passed: прежние 10 проверок и новые проверки контракта, цитат, ошибок модели, CSV, источников и фильтрации.
- Разметка 700 синтетических document IDs с несколькими темами: CSV roundtrip пройден; неизвестные темы/повторные ID отклоняются. Это не тест полного RAG на 700 настоящих документах.
- Тема применяется до top-k в обоих retrieval компонентах.
- Внешние private/loopback/link-local адреса блокируются; соединение к публичным источникам привязано к проверенному IP.
- Проверена открытая страница МФТИ: HTML извлечен, сохранены блоки/строки таблиц; полный поиск и ответ выполнились с URL именно этой страницы, без добавления тестового источника в постоянную базу.
- Streamlit AppTest: реальный вопрос дает ожидаемый срок, ошибок нет; старый ответ скрывается при изменении вопроса. Итоговый JSON проверки хранится в reports/answering_ui_smoke.json.

Два простых ответа содержат по одной подтверждаемой цитате. Негативный вопрос получил отказ. Процедурный вопрос отмечен partial: выбраны только часть действий, поэтому инструкция пока неполна. Это 3 успешных и 1 частичный сценарий в малом smoke-наборе, а не обобщенная accuracy. Все выведенные цитаты сверены на вхождение в переданные фрагменты; семантика и полнота оцениваются отдельно.

CPU/CUDA таблица — наблюдаемые последовательные прогоны, не строгий benchmark: warm/cache эффекты не разделены; между проверками сделана небольшая очистка границ цитат/HTML-блоков, а не обучение модели. Нельзя считать отношение времени универсальным ускорением для любой нагрузки.

## CUDA: что подключено

Установлены в tools/llama-cuda124 официальная CUDA-сборка llama.cpp и CUDA 12.4 runtime DLL. SHA256 архивов зафиксированы в answer-runtime.lock.json. NVIDIA-драйвер уже был установлен, версия 566.07; nvidia-smi показывает поддержку CUDA 12.7. Эта строка означает возможности драйвера, а не наличие полного Toolkit.

CUDA runtime обнаружил RTX 3050 Laptop GPU. Запуск настроен на 24 GPU layers и context 8192; llama-server появился как вычислительный процесс C в nvidia-smi. Общая занятая VRAM после загрузки наблюдалась около 3,3–3,5 GiB из 4 GiB, включая рабочий стол/браузеры; память одного процесса отдельно не измерена. Это гибридный GPU+CPU запуск, не перенос всей программы на GPU.

PyTorch остается 2.6.0+cpu, поэтому torch.cuda.is_available() для него возвращает false. Это не противоречит CUDA-инференсу LLM: llama.cpp использует собственный CUDA backend. Retrieval и reranker оставлены на CPU, чтобы не конкурировать за ограниченные 4 GB VRAM. Полный CUDA Toolkit/nvcc и обучающий стек не устанавливались.

## Ограничения и следующие задачи

Утвержденный список тем пока не получен: config/topics.json пуст, механизм загрузки/разметки готов. В присланном DOCX есть описание корпуса и критерии, отдельной таксономии нет. Документы доступны без фильтра тем. Темы не назначаются автоматически моделью.

Нет доказанной безошибочности, полноценной проверки entailment и автоматического применения отмен/редакций. Возможные конфликты пока не проверены на размеченных реальных парах. Сканы внешних PDF передаются в первую часть для OCR; страницы с авторизацией/обязательным JavaScript не поддерживаются. Полный Docker/CUDA deployment и нагрузка на 600–700 настоящих документах не проверены.

Следующие итерации: согласованный список тем и разметка; gold набор вопросов/шагов; полнота процедур; quality/latency по holdout; реальные конфликты и версии. Новые изменения сравнивать с metrics/answering_v1.json, сохраняя модель, контекст и протокол измерений.
