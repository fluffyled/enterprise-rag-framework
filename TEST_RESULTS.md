# Фактические результаты проверки

Дата: 11.11.2026. Финальная модель: Qwen2.5-3B-Instruct Q4_K_M, llama.cpp CPU b12284. Прогон выполнен на реальных документах основного датасета. Не является официальной оценкой хакатона или репрезентативным benchmark.

## Автоматические проверки

- pytest: 10 passed (валидаторы, DOCX-порядок блоков, XLSX-координаты/формулы, уникальность ID и покрытие всех файлов). В чистом репозитории без закрытого корпуса одна интеграционная проверка пропускается.
- pip check: No broken requirements found.
- Все 20 файлов обработаны без ошибок; 3079 фрагментов; 79 PDF-страниц, OCR на 44 страницах.
- Индексация E5-small CPU: около 87 секунд в наблюдаемом прогоне.
- Локальные HTTP health endpoints UI и LLM вернули 200. Финальная проверка интерфейса описана ниже.
- Docker не установлен: Dockerfile/Compose подготовлены, сборка и запуск не проверены.

Полный machine-readable лог: reports/evaluation.json. Эти файлы содержат производные внутренних документов и исключены из Git.

## Предыдущие неуспешные проверки

Исходная Qwen1.5B давала ложные отказы, ошибки JSON и нерелевантные выборки. Один из промежуточных прогонов не отказал на вопрос без ответа. Это не замалчивается: сохранены reports/evaluation_initial.json и reports/evaluation_1_5b_selection.json. После замены на 3B и constrained schema выполнен полный повтор восьми сценариев; значения выше относятся только к финальному прогону.

## Что требует следующего этапа

Полная инструкция, multi-document полнота, обнаружение реальных конфликтов, ручная верификация цепочек редакций, более широкая разметка релевантности и оценка OCR остаются ограничениями baseline. Эти улучшения сейчас не реализуются.
## Проверка интерфейса

Streamlit AppTest: загрузка и отправка реального перефразированного вопроса прошли без exceptions и error сообщений; ожидаемый срок появился в ответе, показаны 6 раскрываемых источников. Это проверка пользовательского сценария через тестовый runtime Streamlit; визуальная проверка браузером и Docker не выполнялись.
