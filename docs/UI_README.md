## Запуск в VS Code / Windows

Откройте папку проекта на диске D: в VS Code, затем PowerShell Terminal:

```powershell
Set-Location D:\хакатон
. .\project-env.ps1
.\.venv313\Scripts\python.exe -m streamlit run app.py --server.port 8503
```

Откройте http://127.0.0.1:8503. Остановка — Ctrl+C в терминале.
Python 3.13. Для отдельного UI окружения, без весов моделей:

```powershell
. .\project-env.ps1
uv venv --python 3.13 .venv-ui --seed
.\.venv-ui\Scripts\python.exe -m pip install -r requirements-ui.txt
.\.venv-ui\Scripts\python.exe -m streamlit run app.py --server.port 8503
```

Демо не импортирует Retrieval и не запускает модели. GPU для UI не нужен. ML-вычисления интерфейс не меняет. Запуск `answer_app.py` и эксперименты остаются отдельными.

## Возможности

Пять экранов: ассистент, документы, история, настройки, описание проекта. Название можно изменить для другой организации. Светлая и тёмная темы. Восемь явно вымышленных демосценариев. Простой и многоисточниковый ответ, инструкция, частичный ответ, отсутствие сведений, неоднозначность, ошибка, длинное название документа.

Карточка вопроса подставляет текст. Отправка — кнопкой или Ctrl+Enter; Enter оставляет перевод строки. Повтор подставляет исходный вопрос для осознанной отправки. Streamlit rerun не повторяет генерацию. История — просмотр результатов, новый диалог, избранное, удаление. Предыдущие сообщения не подаются модели.

Цитаты `[n]` ведут к соответствующему источнику, текст можно раскрыть и скопировать. Экспорт Markdown/TXT включает ответ, режим, статус и источники. Отзывы сохраняются только локально и не запускают обучение.

## Хранение и загрузка

По умолчанию история и настройки в памяти сессии. На странице настроек можно включить сохранение в `data/ui/workspace.json`, а после перезапуска явно загрузить его. Отключение удаляет сохранённый workspace. Сценарий рассчитан на одного локального пользователя, без аутентификации и публичного размещения.

PDF/DOCX/XLSX до 20 МБ сохраняются по SHA-256 в `data/ui/staging/<session>/`; имена пользователя не используются как пути. Список и фильтры отражают реальные файлы текущего рабочего пространства. Удаление убирает файл с диска. Загрузка НЕ выполняет разбор документа, OCR, макросы или индексацию. Статус — «Загружен · ожидает подключения индексации». Это не подтверждение корректности содержимого формата. Системные документы доступны только для просмотра.

Staging сохраняется до удаления; при выключенной истории список исчезнет с окончанием сессии, сами файлы останутся на диске. Не используйте загрузку для неограниченного хранилища. Отзывы — `data/ui/feedback/`; отдельная кнопка удаляет отзывы. Эти каталоги игнорируются Git. Никакие внутренние документы в код и demo fixtures не включены.

Ссылка проверяется синтаксически, импорт отключён. Будущий backend должен отдельно проверять домены, DNS/SSRF, redirects и содержимое. UI не запрашивает URL.

## Подключение

На боковой панели выберите «Подключённый». Существующий `answering.bridge.BaselineSearch` загружается только по запросу; `answering.core.generate` вызывает существующую Qwen. Сами алгоритмы не изменены. Это адаптер к текущему baseline, не объединение с веткой напарника. Признак наличия индекса не выдаётся за успешную загрузку поискового сервиса. Кнопка проверки выполняет отдельный health-check Qwen.

Переменные:

| Переменная | Назначение |
|---|---|
| `ANSWER_LLM_ENDPOINT` | Локальный endpoint Qwen, по умолчанию `http://127.0.0.1:8081/v1/chat/completions` |
| `UI_TITLE` | Начальное название рабочего пространства |
| `UI_DATA_DIR` | Локальное UI-хранилище, по умолчанию `<project>/data/ui`; на Windows только D: |

Нельзя подставлять прежний Qwen2.5 из legacy Compose вместо Qwen3.5. Запускайте уже подготовленный сервер Qwen3.5 по ANSWERING.md. Новый UI не запускает и не перенастраивает модель. Для интеграции нового backend замените только `connected(request)` в `ui/services.py`, сохранив контракт. `answer_style` передаётся в адаптер, но нынешний генератор его не поддерживает; интерфейс предупреждает об этом. Поисковые фильтры отключены до реализации поддержки backend.

## Docker UI

```powershell
docker compose -f compose.ui.yaml up --build
# остановка
docker compose -f compose.ui.yaml down
```

Это только UI Demo, без ML-сервисов. Docker не установлен на этой машине, сборка не проверена. Docker Desktop должен использовать хранилище диска D: согласно политике пользователя. Старый ML Compose сохранён; его app image получил необходимые UI-файлы, но его старый LLM-сервис не является текущей Qwen3.5.

## Проверки и ограничения

`python -m pytest -q`: 51 passed на Python 3.13. Проверены AppTest: главная, карточка вопроса, ответ, отсутствие повторной генерации при rerun, избранное, открытие/удаление диалога, документы, настройки, тема. Отдельно проверены все demo fixtures, неизвестный вопрос, неверный backend, недоступная LLM, staging, path traversal, расширение/размер и удаление.

Браузерная проверка выполнялась на localhost. Это UI-изменение: новые метрики качества генератора и benchmark-результаты не измерялись. Connected happy-path с новой генерацией в этой работе не подтверждён. Полноценный preview PDF/DOCX, ingestion, права доступа, автоматическое определение редакций и потоковый вывод остаются за границами этого UI.

Дополнительно проверено в браузере: подстановка карточки, получение demo-инструкции, раскрытие цитаты, переключение тем, загрузка тестового PDF в staging и его удаление, адаптивная компоновка при ширине 390 px. После визуальной проверки исправлены контраст тёмной темы и отступ под верхней панелью на узком экране. Снимки: reports/ui/interface.jpg и reports/ui/mobile.jpg (локально, не в Git). Кнопка копирования показала успешный результат browser API; независимое чтение системного буфера через используемый браузерный инструмент недоступно. Экспорт проверяется на уровне сформированного текста. Фактическая загрузка XLSX/DOCX и переполнение browser upload не проверялись вручную; соответствующие ограничения staging покрыты автоматическим тестом.
