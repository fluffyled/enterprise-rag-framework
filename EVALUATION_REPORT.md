# Проверки интеграции

## Регрессия условий в списках

На сохранённых ответах модели для Q031 и Q032 повторно выполнена сборка G2 из исходного пункта 4. Видимое резюме сохраняет условие о договорах, заключённых после утверждения регламента, и исключение соответствующего подпункта. Вводная фраза и подпункт приложены как две дословные выдержки. Регрессионный тест также покрывает случай, когда модель отклонила неполную переформулировку.

Новые сквозные попытки Q031 и Q032 завершились сетевой ошибкой Windows `WinError 10013` на обращениях к локальному llama-server. Проверка на сохранённых данных изолирует сборку ответа и не измеряет качество свежего GPU-прогона. Приведённые ниже метрики относятся к предыдущей реализации.

На Windows прошли 129 тестов. Среди регрессий — разные документы с одинаковым SHA, одинаковые значения в разных ячейках DOCX, сохранение предыдущего снимка и диагностика повреждённого DOCX, разбор годов и совместная проверка фрагментов из разных пакетов. Сравнение лимитов 4/8/адаптивный, независимая оценка всего complex50 и Linux CI остаются открыты.

## Полный тракт Fast + Legacy

Для всех 150 вопросов запущены BGE-M3, BGE-reranker-v2-m3 и Legacy поверх Qwen3.5-4B Q4_K_M. Поиск использовал зафиксированный BGE-индекс. Эталонные ответы и факты использовались только для подсчёта. Четыре строки, затронутые сбоем памяти и сетевого доступа при первоначальном прогоне, пересчитаны с ограниченным RAM-кэшем llama-server. Исходный и восстановленный замеры лежат в локальном `reports/generation-research/`.

| Метрика | complex50 | rag100 |
|---|---:|---:|
| Вопросов | 50 | 100 |
| Лексические совпадения с фактами / ответами | 14/224 (6,3%) | 44/92 (47,8%) |
| Вопросы со всеми лексическими совпадениями | 0/50 | 44/92 |
| Недостаточно данных при наличии ответа | 4/50 | 1/92 |
| Корректные отказы на неотвечаемых вопросах | — | 8/8 |
| Дословные цитаты / показанные цитаты | 137/137 | 124/124 |
| p50 / p95, с | 3,724 / 5,581 | 3,058 / 7,829 |

Статусы complex50: 46 частичных и 4 отказа. Статусы rag100: 89 частичных, 9 отказов и 2 возможных противоречия. После повторов технических ошибок в итоговой выборке нет. По всем 150 вопросам p50 составила 3,1815 с, p95 — 6,718 с. Восстановленная выборка включает холодный старт при повторе. Совпадение цитаты означает её наличие в показанном фрагменте. Лексическое совпадение использует порог 70% слов эталона и не измеряет смысловую точность.

Контроль исходников, формата ответа и отображения — 123 теста прошли.

## Контрольный тракт Quality + G2

HQ004, HQ014 и HQ022 получили частичные ответы за 181,011, 394,248 и 142,394 с соответственно. Лексически совпали 2 из 13 фактов. Q031 и Q032 получили частичные ответы за 142,202 и 100,594 с, оба без лексического совпадения с эталоном. Все 69 показанных цитат найдены в соответствующих фрагментах. На HQ048 соединение с локальным сервером оборвалось в двух попытках. Полноценной метрики Quality + G2 на 150 вопросах пока нет.

## Ранее выполненные проверки

Реальный сквозной сценарий прошёл в Streamlit AppTest с локальными BGE-M3, BGE-reranker-v2-m3 и Qwen3.5-4B Q4_K_M. DOCX был загружен через staging и проиндексирован новым корпусом. На вопрос о сроке подачи заявки Quality и G2 показали «за три рабочих дня», ссылку [1], точную цитату и локатор «п. 1». После удаления файла и перестройки поиск вернул статус недостаточности данных для пустого корпуса.

| Замер | Поиск с загрузкой модели | Генерация |
|---|---:|---:|
| DOCX, один пункт | 7,397 с | 8,233 с |
| Вопрос о найме, существующий корпус, ранний интеграционный прогон | 20,648 с | 296,407 с |

На финальном коде Streamlit повторно показал тот же срок, роль и адресата с Quality/G2. Во время параллельной оценки поиск занял 20,960 с с загрузкой моделей, генерация 15,103 с. Fast/G2 на прогретом индексе также дал верную цитату; генерация заняла 175,491 с, включая конкурирующие запросы в очередь единственного слота. Эти времена не используются как показатели изолированной производительности.

Во время раннего прогона занято 7420 из 8192 МиБ VRAM при одновременной работе поиска и LLM. Это снимок, пиковый расход не измерялся. На LLM отдельно наблюдалось 3676 МиБ с учётом остальных потребителей GPU.

`pytest -q` — 119 тестов прошли. Windows launcher прошёл проверку запуска модели, пробной генерации, готовности Streamlit и завершения обоих процессов с `-GpuLayers 0` и `-GpuLayers 24`. Изолированный Quality/Legacy вернул верную цитату (20,396 с с загрузкой поиска и 1,388 с генерации). При остановке зависшего сервера в другом прогоне приложение вернуло технический статус `error`; после перезапуска ответ восстановился.

Fast на complex50 воспроизвёл выбранные фрагменты по ID и тексту для всех 50 вопросов. Document-aware clause recall 0,707417, strict recall 0,645190; весь набор итоговых retrieval-метрик совпадает с FREEZE_fast.

Quality (H1) на тех же 50 вопросах воспроизвёл выбранные фрагменты по ID и тексту. Document-aware clause recall 0,895524, strict recall 0,845190; итоговые retrieval-метрики совпадают с FREEZE_quality.

H4 на тех же 50 вопросах воспроизвёл выбранные фрагменты по ID и тексту и все итоговые метрики при повторном использовании сохранённых планов поиска. Document-aware clause recall 0,909048, strict recall 0,844714. Повторное получение планов от LLM в этом сравнении не проверялось.

Исторические показатели retrieval и Oracle доступны в [RETRIEVAL_FREEZE_REPORT.md](RETRIEVAL_FREEZE_REPORT.md) и [GENERATION_150_REPORT.md](GENERATION_150_REPORT.md). Историческое лексическое покрытие Oracle не используется как оценка смыслового качества интеграции.

Контроль HQ004 на Oracle вновь выявил пропуски передачи результата автору и закрытия без обратной связи. Исследовательский генератор выставил `answered`. Application Service понижает такой статус до `partial` для любого вопроса.

Предыдущий Oracle-прогон завершил запись 150 строк, из которых 107 получили ошибки подключения к локальному серверу. Его агрегаты не подходят для оценки качества. Повтор HQ014 показывает смешение вариантов в исследовательском профиле. Полное парное сравнение и независимая смысловая разметка ещё не выполнены.

Первые контрольные результаты Oracle по известным случаям: HQ004 — `answered` с двумя пропусками, HQ014/HQ022/HQ048 — `partial`, Q031 — `error` после отклонения цитаты, Q032 — `answered` по оценке генератора. Эти статусы относятся к исследовательскому прогону.
