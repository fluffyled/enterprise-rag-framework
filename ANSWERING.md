# Вторая часть: короткие ответы по документам МФТИ

Рабочая ветка: `developer-2/answer-generation`. Новый код расположен в `answering/` и `answer_app.py`. Файлы `navigator/` первой части не изменены. Существующий поиск подключен временным адаптером `answering/bridge.py`; независимый режим принимает JSON найденных фрагментов и не требует Haystack/PyTorch.

## Что получает сотрудник

Вопрос → 1–2 цитируемых предложения из документов → название документа и пункт/страница. Для процедуры показывается отдельный раскрываемый список действий. Если данных недостаточно — отказ, если покрыта только часть — явный статус partial. Возможные конфликты требуют двух цитат. Свободный текст модели не выводится пользователю.

Модель выбирает ID предложений; программа извлекает текст из источника и проверяет точное вхождение. Это ограничивает появление придуманных фактов, но **не гарантирует релевантность, полноту и юридическую применимость цитаты**. Не обещаем «нулевые ошибки». Подробности текущей проверки: ANSWERING_RESULTS.md.

Присланные 12.11.2026 DOCX и ZIP сверены: 20 файлов ZIP побайтно совпадают с уже обработанным корпусом. Отдельного утвержденного перечня тем в DOCX нет. Повторная распаковка и индексация не понадобились.

## Запуск на подготовленном компьютере

```powershell
.\start-answer.ps1
```

Интерфейс: http://127.0.0.1:8502. Локальная LLM: http://127.0.0.1:8081. Остановка:

```powershell
.\stop-answer.ps1
```

CUDA включена по умолчанию: llama.cpp b12284 CUDA 12.4, 24 GPU layers, context 8192, один slot. CPU-режим для диагностики/сравнения при наличии прежнего CPU runtime:

```powershell
.\start-answer.ps1 -Cpu
```

Не запускайте два сервера на одном порту. Логи и PID-файл хранятся в исключенных reports/ и data/. stop-answer проверяет путь исполняемого файла и останавливает только сохраненные процессы второй части.

## Установка на другой Windows-компьютер

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-answer.txt
.\.venv\Scripts\python.exe scripts/download_answer_model.py
.\.venv\Scripts\python.exe scripts/download_answer_runtime.py
.\start-answer.ps1
```

Нужен подходящий NVIDIA-драйвер для CUDA 12.4 runtime. CUDA-сборка и DLL загружаются из официального релиза llama.cpp с проверкой SHA256 в answer-runtime.lock.json. Полный CUDA Toolkit, nvcc и Visual Studio Build Tools для готовой сборки не нужны. CPU-вариант runtime отдельно описан в исходном README.

Для независимой работы используйте JSON-режим UI или CLI. Для режима локального поиска дополнительно нужны зависимости первой части, модели E5/reranker и подготовленный data/index.json, описанные в исходном README. Без него UI предлагает JSON-режим; сам ingestion/OCR в этой части не повторяется.

Сетевая подготовка: PyPI, Hugging Face, GitHub. Во время ответа документы передаются только локальному HTTP endpoint; env ANSWER_LLM_ENDPOINT допускает loopback или имя llm для локальной Docker-сети. Редиректы и HTTP proxy для LLM отключены. Токены облачных API не требуются.

## Контракт с первым разработчиком

Вход: объект `schema_version: 1`, поле `fragments` — до 100 результатов поиска. Обязательные поля каждого фрагмента:

| Поле | Значение |
|---|---|
| id | Уникальный ID фрагмента в снимке корпуса |
| document_id | Стабильный идентификатор документа для разметки тем |
| text | Текст фрагмента, который действительно получен из документа |
| title | Название источника |
| locator | Страница, пункт, абзац или строка |

Необязательные поля: topic_ids (список ID тем), url (HTTP/S ссылка), date_hint (подсказка, не доказательство актуальности), order (исходный порядок), complete (boolean, по умолчанию false). complete=true означает, что передан целый исходный блок/строка, а не обрезанное окно. Это позволяет цитировать строки таблиц без точки; не ставьте флаг на обрывках.

Пример синтетического входа, не содержащий регламентов: examples/search_bundle.json. Сам контракт и проверка: answering/contracts.py.

```powershell
.\.venv\Scripts\python.exe -m answering examples/search_bundle.json "Кто подает заявку в учебном примере?"
```

Выход: schema_version, status (answered/partial/insufficient/conflict/error), answer, steps, conflicts, warnings. Каждая цитата содержит fragment_id, document_id, quote, title, locator, url, topic_ids. ID сохраняются, UI не связывает источники только по изменяемым позиционным номерам. Код ошибки отдельно от отсутствия ответа.

Если первый разработчик заменит embeddings, reranker или storage, достаточно сохранить этот входной контракт. Модуль генерации не должен читать его внутренний индекс. bridge.py является временной интеграцией, которую можно заменить адаптером к готовому API; новый веб-сервис для этого пока не нужен.

## Открытые внешние ссылки

Вкладка «Источники и темы» → вставить до пяти ссылок → «Загрузить страницы». Загружаются HTML, text/plain, PDF с текстовым слоем. Сохраняются конечный URL, дата получения UTC, SHA256, заголовок и исходные блоки. HTML-таблицы сохраняют пары заголовок/значение в строках. Загруженные страницы участвуют в том же поиске, цитаты содержат URL.

Страницы с авторизацией или обязательным JavaScript не поддерживаются. Сканы PDF нужно передать первой части для OCR. Ограничение файла 5 MiB, PDF до 80 страниц, текст до 120 000 символов. Удаляются script/style/navigation; JavaScript не выполняется. Перед каждым redirect заново проверяется публичность адреса, соединение привязано к проверенному IP; локальные/private/link-local адреса и служебные порты блокируются. Это не веб-поисковик и не обход закрытых сайтов. Открытые страницы могут содержать ошибочные или вредоносные тексты: точное цитирование не заменяет содержательную проверку.

Внешние тексты и URL-кэш находятся в data/external_sources.json и не публикуются в Git. Внешним сайтам отправляется только обычный GET по указанной ссылке, не вопрос сотрудника и не внутренние регламенты.

## Темы и подготовка к 600–700 документам

Текущий config/topics.json пуст до получения утвержденных названий. Темы не выдумываются моделью. В UI можно загрузить утвержденный JSON вида:

```json
{"schema_version": 1, "topics": [{"id": "approved-id", "name": "Название из утвержденного списка"}]}
```

Рабочий каталог сохраняется в data/topics.json. Привязка документов хранится в data/document_topics.csv: столбцы document_id,topic_ids; несколько тем разделяются `;`. В UI доступны редактор, экспорт CSV для массовой разметки и импорт. Неизвестные темы и повторные ID отклоняются. Один документ может иметь несколько тем.

Выбранная тема фильтрует и BM25, и dense retrieval **до объединения top-k**. Без выбранной темы доступны все документы, включая неразмеченные. Фильтрация не является контролем доступа: первый разработчик должен отдельно реализовать права пользователей, если они нужны.

Формат разметки проверен на 700 синтетических документах. Полный поиск/инференс по 700 настоящим документам пока не измерен. Для роста корпуса первый разработчик сохраняет тему в metadata, отвечает за индексирование/обновления и при необходимости меняет storage. Нельзя отправлять все 700 документов в prompt; генератор получает только найденный контекст.

## Готовая LLM, собственная модель и обучение

Сейчас используется готовая Qwen3.5-4B, квант Q4_K_M из unsloth/Qwen3.5-4B-GGUF; исходная модель Qwen/Qwen3.5-4B, Apache-2.0. Revision, filename и SHA256 зафиксированы в answer-model.lock.json. Это инференс готовых весов, не обучение.

Для 600–700 изменяющихся регламентов RAG практичнее запоминания документов в весах: обновляются источники и индекс, остаются ссылки и версии. Готовую модель можно использовать сразу. Маленькую учебную LLM с нуля создать можно, но обучение модели сопоставимого качества требует большого корпуса, вычислений и отдельной экспертизы; текущие 16 GB RAM / 4 GB VRAM для такого проекта непрактичны.

LoRA/QLoRA — возможный следующий этап для исправления устойчивых ошибок формата/выбора на размеченных примерах. Это не замена поиску и проверке актуальности. Сначала нужны train/dev/test, примеры отказов, отсутствие утечки документов между split и сравнение с неизмененной базой. На 4 GB VRAM обучение выбранной 4B без отдельного замера не обещается. Никакое обучение и установка обучающего стека сейчас не выполнялись.

Источники: [Qwen3.5-4B](https://huggingface.co/Qwen/Qwen3.5-4B), [GGUF](https://huggingface.co/unsloth/Qwen3.5-4B-GGUF), [LoRA/PEFT](https://huggingface.co/docs/peft/main/en/conceptual_guides/lora), [совместимость CUDA](https://docs.nvidia.com/deploy/cuda-compatibility/minor-version-compatibility.html).

## Хранение только на D:

Проект Windows должен находиться на D:. Модели — models/, CUDA и OCR — tools/, окружение — .venv/, индексы — data/, отчеты — reports/. Кэши pip, Hugging Face, PyTorch и sentence-transformers, а также временные файлы приложения направлены в .cache/ внутри проекта. Обе команды запуска подключают project-env.ps1; модуль answering и загрузчики также устанавливают эти пути до импорта модельных библиотек. Запись новых Python bytecode-кэшей отключена.

Перед ручной установкой пакетов или запуском инструментов в PowerShell:

```powershell
Set-Location D:\хакатон
. .\project-env.ps1
.\.venv\Scripts\python.exe -m pip install -r requirements-answer.txt
```

На этом компьютере пути библиотечных кэшей дополнительно сохранены в пользовательских переменных среды (`project-env.ps1 -PersistCaches`); новые приложения получают их после обновления окружения/перезапуска. Системные TEMP/TMP, расположение существующих Python, VS Code и Codex не менялись. TEMP/TMP перенаправляются только для процессов проекта. gdown не используется новыми загрузчиками; при разовом повторном запуске gdown отключайте cookies (`--no-cookies`), поскольку его собственный путь cookies жестко привязан к профилю пользователя.

Проверка путей: `.\.venv\Scripts\python.exe -m pytest tests/test_storage.py -q`. Кэш и данные исключены из Git. Небольшие системные журналы, настройки сторонних программ и файл подкачки Windows не контролируются проектом.
